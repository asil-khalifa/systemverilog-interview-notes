# Constraint-Writing Questions

Constraint writing is the most common hands-on question in a DV interview. The interviewer describes a set of legal values in words and you write the constraint. Three habits earn marks:

- Declare the variable with the right width and state it ("I assume `x` is an 8-bit unsigned value").
- Think about expression width and overflow before writing any arithmetic.
- After writing, test the constraint mentally with one legal and one illegal value.

Each solution below is a complete class, followed by a one-line explanation.

## Single Variables

**Q220. A value between 10 and 50, but not between 20 and 30.**

```systemverilog
class c220;
  rand bit [7:0] x;
  constraint x_c {
    x inside {[10:50]};
    !(x inside {[20:30]});
  }
endclass
```

Two constraints are ANDed. Equivalent in one line: `x inside {[10:19], [31:50]};`.

**Q221. An even number; then a multiple of 4.**

```systemverilog
class c221;
  rand bit [7:0] e, m;
  constraint even_c { e % 2 == 0; }       // or  e[0] == 0
  constraint mul4_c { m[1:0] == 2'b00; }  // or  m % 4 == 0
endclass
```

A bit-select is cheaper for the solver than `%` and says the same thing for powers of two.

**Q222. A length that is small (1 to 8) 70% of the time and large (9 to 64) 30% of the time.**

```systemverilog
class c222;
  rand bit [6:0] len;
  constraint len_c { len dist { [1:8] :/ 70, [9:64] :/ 30 }; }
endclass
```

`:/` divides each weight over its range, so the two ranges have total weights 70 and 30. With `:=` each of the 56 values in the second range would have weight 30 and the large values would dominate.

**Q223. ALU opcodes: ADD and SUB 40% each, the six other opcodes sharing the remaining 20%.**

```systemverilog
class c223;
  rand alu_op_e op;
  constraint op_c {
    op dist { ALU_ADD := 40, ALU_SUB := 40, [ALU_AND:ALU_SHR] :/ 20 };
  }
endclass
```

The enum values 2 to 7 are covered by one range, and `:/` splits the weight 20 among them.

**Q224. Exactly one bit set in a 16-bit value (one-hot).**

```systemverilog
class c224;
  rand bit [15:0] x;
  constraint onehot_c { $onehot(x); }     // or  $countones(x) == 1
endclass
```

Without system functions: `x != 0; (x & (x - 1)) == 0;`. The same constraint answers "generate a power of two".

**Q225. Exactly five bits set in a 16-bit value.**

```systemverilog
class c225;
  rand bit [15:0] x;
  constraint five_c { $countones(x) == 5; }
endclass
```

`$countones` is allowed in constraints. A loop-based alternative sums the bits: `x[0] + x[1] + ...` written with care for width (each bit must be widened before adding).

**Q226. No two adjacent bits set in an 8-bit value.**

```systemverilog
class c226;
  rand bit [7:0] x;
  constraint no_adj_c { (x & (x >> 1)) == 0; }
endclass
```

Shifting by one lines each bit up with its neighbour; if the AND is zero no pair of neighbours is both 1. Add `$countones(x) == 3` to ask for exactly three non-adjacent ones.

**Q227. The upper nibble of a byte is the bitwise inverse of the lower nibble.**

```systemverilog
class c227;
  rand bit [7:0] x;
  constraint inv_c { x[7:4] == ~x[3:0]; }
endclass
```

Both sides are 4 bits wide, so the inversion does not introduce extra upper bits. Had the right side been compared with a wider value, `~` would have been applied after extension, giving wrong upper bits.

**Q228. A 32-bit address that is word-aligned, lies in the range 0x1000 to 0x1FFF, and for which a burst of `len` bytes does not cross the end of the range.**

```systemverilog
class c228;
  rand bit [31:0] addr;
  rand bit [7:0]  len;
  constraint addr_c {
    addr[1:0] == 2'b00;
    addr inside {[32'h1000:32'h1FFF]};
    len inside {[1:64]};
    addr + len <= 32'h2000;
  }
endclass
```

`addr + len` is evaluated in 32 bits; because `addr` is at most 0x1FFC and `len` at most 64, the sum cannot overflow. State that reasoning; it is what the interviewer is checking.

**Q229. A value that is different from the value generated by the previous call.**

```systemverilog
class c229;
  rand bit [3:0] x;
  bit      [3:0] prev;                    // state variable, not random
  constraint diff_c { x != prev; }
  function void post_randomize();
    prev = x;
  endfunction
endclass
```

`prev` is a non-random variable, so the solver treats it as a constant; `post_randomize()` updates it after every successful call. (The first call can never return 0, the initial value of `prev`; initialise `prev` differently if that matters.)

**Q230. Every value of a 3-bit variable exactly once before any repeats, without using `randc`.**

```systemverilog
class c230;
  rand bit [2:0] x;
  bit      [2:0] used [$];
  constraint new_c { !(x inside {used}); }
  function void post_randomize();
    used.push_back(x);
    if (used.size() == 8) used.delete();  // all eight seen: start a new cycle
  endfunction
endclass
```

The queue records the values already used; `inside` accepts an array as its set, and an empty array matches nothing. This is how cyclic behaviour is built when `randc` is not usable, for example when the cycle must cover a pair of variables.

## Relations Between Variables

**Q231. A packet kind decides the legal payload length: SHORT 1 to 8, MEDIUM 9 to 63, LONG 64 to 255.**

```systemverilog
class c231;
  typedef enum {SHORT, MEDIUM, LONG} kind_e;
  rand kind_e    kind;
  rand bit [7:0] len;
  constraint len_c {
    (kind == SHORT)  -> len inside {[1:8]};
    (kind == MEDIUM) -> len inside {[9:63]};
    (kind == LONG)   -> len inside {[64:255]};
  }
  constraint order_c { solve kind before len; }
endclass
```

Three implications cover the three kinds. Without `solve kind before len`, `LONG` would be chosen about 75% of the time because it has 192 of the 255 (kind, len) solutions; with it, each kind is equally likely.

**Q232. When `flag` is 1, `data` must be 0; `flag` should be 1 about half the time.**

```systemverilog
class c232;
  rand bit       flag;
  rand bit [7:0] data;
  constraint data_c { flag -> data == 0; }
  constraint ord_c  { solve flag before data; }
endclass
```

The implication alone gives 257 solutions, only one with `flag` = 1. The ordering makes the solver pick `flag` first, 0 or 1 with equal probability, and then a legal `data`.

**Q233. Two 8-bit values whose sum does not overflow 8 bits.**

```systemverilog
class c233;
  rand bit [7:0] a, b;
  constraint sum_c { a + b <= 255; }
endclass
```

This is correct because the literal `255` is a 32-bit integer, so `a` and `b` are extended to 32 bits before the addition. The trap is writing `a + b <= 8'd255`: every operand is then 8 bits, the sum wraps, and the constraint is always true. If in doubt, write `int'(a) + int'(b) <= 255`.

**Q234. Three values in strictly increasing order.**

```systemverilog
class c234;
  rand bit [7:0] lo, mid, hi;
  constraint order_c { lo < mid; mid < hi; }
endclass
```

Two separate relations. `lo < mid < hi` compiles but means `(lo < mid) < hi`, which is a different and almost useless constraint (see Q182).

**Q235. A valid calendar date (ignoring leap years).**

```systemverilog
class c235;
  rand int unsigned month, day;
  constraint date_c {
    month inside {[1:12]};
    day   inside {[1:31]};
    (month inside {4, 6, 9, 11}) -> day <= 30;
    (month == 2)                 -> day <= 28;
  }
endclass
```

A general range plus implications for the shorter months. To include leap years add a `rand bit leap;` (or a year with the divisibility rule) and write `(month == 2) -> day <= (leap ? 29 : 28);`.

## Arrays

**Q236. A dynamic array of 5 to 10 elements in strictly ascending order.**

```systemverilog
class c236;
  rand bit [7:0] a [];
  constraint size_c { a.size() inside {[5:10]}; }
  constraint asc_c  { foreach (a[i]) if (i > 0) a[i] > a[i-1]; }
endclass
```

The guard `i > 0` keeps the index `i-1` in range. Using `>=` instead allows equal neighbours. An alternative is to randomize freely and call `a.sort()` in `post_randomize()`.

**Q237. An array with all elements different, without the `unique` keyword.**

```systemverilog
class c237;
  rand bit [3:0] a [8];
  constraint uniq_c {
    foreach (a[i])
      foreach (a[j])
        if (i < j) a[i] != a[j];
  }
endclass
```

Every pair is compared once (`i < j` avoids comparing an element with itself and halves the number of constraints). With the keyword: `constraint uniq_c { unique {a}; }`.

**Q238. An array of five elements, each between 1 and 40, whose sum is exactly 100.**

```systemverilog
class c238;
  rand bit [7:0] a [5];
  constraint elem_c { foreach (a[i]) a[i] inside {[1:40]}; }
  constraint sum_c  { a.sum() with (int'(item)) == 100; }
endclass
```

`sum()` has the width of an element. Without the cast the sum would be computed modulo 256, and values such as 356 would also satisfy the constraint (not reachable here because of the limit of 40, but the cast is the correct habit and the point the interviewer wants to hear).

**Q239. A palindrome array: it reads the same forwards and backwards.**

```systemverilog
class c239;
  rand bit [3:0] a [7];
  constraint pal_c {
    foreach (a[i])
      if (i < $size(a) / 2) a[i] == a[$size(a) - 1 - i];
  }
endclass
```

Each element in the first half must equal its mirror element. The middle element of an odd-length array is unconstrained.

**Q240. Fixed patterns: (a) 0, 1, 0, 1, ... and (b) 0, 0, 1, 1, 2, 2, ...**

```systemverilog
class c240;
  rand bit [3:0] alt [8];
  rand bit [3:0] pair [8];
  constraint alt_c  { foreach (alt[i])  alt[i]  == i % 2; }
  constraint pair_c { foreach (pair[i]) pair[i] == i / 2; }
endclass
```

When the interviewer asks for a pattern, look for a formula in terms of the index. Other favourites: `a[i] == i * i`, `a[i] == (i % 2 ? i : 0)`, and the Fibonacci relation `if (i > 1) a[i] == a[i-1] + a[i-2]`.

**Q241. A 4 by 4 identity matrix; then a matrix in which each row has exactly one 1.**

```systemverilog
class c241;
  rand bit ident [4][4];
  rand bit onehot_rows [4][4];
  constraint ident_c { foreach (ident[i, j]) ident[i][j] == (i == j); }
  constraint rows_c  {
    foreach (onehot_rows[i]) onehot_rows[i].sum() with (int'(item)) == 1;
  }
endclass
```

A two-dimensional `foreach` uses `[i, j]`. For the second constraint, `onehot_rows[i]` is one row, and the reduction method is applied to it with a cast because each element is one bit.

**Q242. A sequence in which each element differs from the previous one in exactly one bit (Gray-code style).**

```systemverilog
class c242;
  rand bit [3:0] a [8];
  constraint gray_c {
    foreach (a[i])
      if (i > 0) $countones(a[i] ^ a[i-1]) == 1;
  }
endclass
```

XOR marks the bits that differ between neighbours; `$countones` requires exactly one such bit.

**Q243. Four memory regions, each with a base address and a length, that do not overlap.**

```systemverilog
class c243;
  rand bit [15:0] base [4];
  rand bit [15:0] len  [4];
  constraint lim_c {
    foreach (base[i]) {
      base[i] <= 16'hF000;
      len[i] inside {[1:256]};
    }
  }
  constraint no_overlap_c {
    foreach (base[i])
      foreach (base[j])
        if (i < j)
          (base[i] + len[i] <= base[j]) || (base[j] + len[j] <= base[i]);
  }
endclass
```

Two regions do not overlap if one ends at or before the start of the other. The limits in `lim_c` guarantee that `base + len` cannot exceed 16 bits; without them the 16-bit sum could wrap and a region near the top of memory would appear to end near address 0.

> **Interview trap:** Constraint expressions follow the same width and sign rules as any other expression (M1). Most wrong constraints written in interviews are wrong because of an overflow in a sum, a signed variable (`int`) that goes negative, or a chained comparison. Check those three things every time.

> **Key point:** If you cannot express a requirement cleanly in constraints, say so and use `post_randomize()`: randomize the easy part, then compute, sort or shuffle the rest procedurally. Knowing when not to fight the solver is a sign of experience.
